# Python 路线实现与讲解说明

本实现完成同步客户端、同步服务端和异步服务端。两个服务端遵循同一协议并共享相同的业务设计；同步版本用于理解线程并发，异步版本是必做交付。

## 数据流与职责

```text
终端命令
  -> 同步 httpx 客户端
  -> HTTP/1.1 + UTF-8 JSON + Bearer token
  -> FastAPI 路由与请求体读取
  -> Service 鉴权和业务规则
  -> 受锁保护的内存用户状态
```

- 客户端负责收集输入、构造请求、保存最近一次登录令牌，并根据 HTTP 状态处理失败。
- HTTP 层负责路径和方法判断、524,288 字节请求体限制、UTF-8 JSON 解析和响应编码。
- `Service` 负责字段校验、密码处理、鉴权、文本隔离、令牌期限和共享状态一致性。
- 每个服务端进程拥有独立内存状态，重启后数据清空。

## 状态模型

`Service.users` 以用户名索引 `User`。每个用户保存：

- 密码盐和 PBKDF2 摘要；
- 当前唯一令牌和固定到期时间；
- 仅属于该用户的 `name -> text` 字典。

再次登录会替换旧令牌。退出会撤销当前令牌。注销账号会在同一临界区内删除用户、令牌和全部文本。同名重新注册会创建新的 `User` 对象，因此旧令牌和旧文本都不能恢复。

## 锁与并发设计

一把 `threading.Lock` 保护所有共享内存状态。鉴权和对应的数据操作在同一次持锁期间完成，避免账号已删除后旧请求重新写入文本。

密码哈希刻意放在锁外，因为 PBKDF2 是耗时的 CPU 工作。登录流程先在锁内取得当前用户对象和摘要，释放锁后计算密码，再次加锁时用对象身份确认用户名仍指向原用户：

```python
if self.users.get(name) is not user:
    # 旧账号可能已注销并被同名新账号替代
```

因此，正在进行的旧账号登录不能把令牌写到同名的新账号上。注册的“检查用户名并写入”、登录的“复查并替换令牌”、鉴权后的文本操作和注销都各自形成原子状态变化。

令牌期限使用 `time.monotonic()` 计算经过时间。测试注入可控时钟，不依赖真实等待，也不受系统时间调整影响。任何受保护操作都会检查期限；操作不会延长令牌有效期。

## 同步与异步执行模型

同步服务端的 FastAPI 同步处理函数由框架在线程池执行，所以同步业务也可能被多个线程同时调用，仍然必须加锁。

异步服务端在事件循环中读取网络请求体，然后使用 `asyncio.to_thread(service.handle, ...)` 执行业务。这样 PBKDF2 等阻塞工作在线程中运行，事件循环仍可处理其他连接。异步测试包含一个受控阻塞业务调用，并确认阻塞期间 `/ping` 仍能完成。

锁只保护内存状态，不在持锁期间等待网络。HTTP 响应编码和发送发生在业务锁释放之后。

## 输入边界

- 用户名：1–32 个 ASCII 字母、数字、下划线或连字符。
- 密码：8–128 个 Python Unicode 字符，并通过 UTF-8 编码拒绝未配对代理码位。
- 文本名：1–64 个 ASCII 字母、数字、下划线或连字符。
- 文本和 echo：允许空字符串、Unicode 和换行，最多 65,536 个 UTF-8 字节。
- HTTP 请求体：最多 524,288 字节，限制在 JSON 解析前执行。
- 请求对象只允许协议列出的必填字段，不做自动类型转换。

客户端多行输入以单独一行 `:end` 结束；`\:end` 表示正文中的字面量 `:end`。立即结束可表达空文本，结束前的空行可表达末尾换行。

## 运行

三个目录是独立项目，分别进入目录安装锁定依赖：

```bash
uv sync --locked
```

启动异步服务端：

```bash
cd projects/python/server-async
uv run rm-server --host 127.0.0.1 --port 7878 --token-ttl-seconds 300
```

另开终端启动客户端：

```bash
cd projects/python/client-sync
uv run rm-client --url http://127.0.0.1:7878
```

可用命令为 `ping`、`register`、`login`、`logout`、`list`、`echo`、`delete-user`、`put`、`get`、`delete` 和 `q`。
